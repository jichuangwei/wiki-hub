每周一 09:00（Asia/Shanghai）制作上一完整自然周（周一至周日）的 AI × Agent × 前端周报：沿用模板固定五类，每类 2–4 条，共 10–20 条；重点资讯的深入分析放在对应资讯内，不追加独立深度栏目。测试指定周次时使用指定日期，不改正式任务定时设置。

开始时，必须通过已连接的 GitHub 从 jichuangwei/wiki-hub 的 main 分支完整读取 skills/ai-agent-frontend-weekly/cloud-task-prompt.txt，记录 Prompt blob SHA；随后完整读取 skills/ai-agent-frontend-weekly/SKILL.md 并记录 Skill blob SHA，按该 skill 执行；再完整读取 templates/news/ai-agent-frontend-weekly-email.html 并记录模板 blob SHA。仓库中的三个文件是本次运行的规则与排版源，不使用旧缓存或记忆代替。任一文件读取失败，停止发布和发信并说明原因。

发布前必须确认当前任务可调用 get_publication_by_week、publish_weekly_report 和 get_publication_status。先按周查询现有记录，再按 skill 选择复用、首次发布或经用户明确批准的修订；不能因同周冲突而普通重试或覆盖。首次发布或获批修订通过 Wiki Hub Publisher 触发 GitHub Actions；保存 request_id，核实该请求对应的真实周报归档 commit 已由 GitHub Actions 提交到 main，并从该 commit 完整读取归档 HTML，确认周期正确、正文与待发送邮件一致。满足这些条件即可按 skill 通过 Gmail 发送完整 HTML 邮件，不等待 Actions 全流程结束、Pages 部署或线上内容验证。state=published、action_conclusion=success、online_verified=true 不作为发信前置条件；deployed_unverified、online_verified=false 仅用于状态报告，不阻塞邮件或任务完成，不为等待其变化而持续轮询，也不要求人工确认。Actions、Pages 和线上内容仍做独立检查并如实报告；发布工具不可用、无法确认真实归档 commit 或正文一致时停止发信并说明原因，Actions 失败或线上未核实按实际状态报告，未验证成功不得声称部署验证成功。
